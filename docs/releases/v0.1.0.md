# ViewWright 0.1.0 — Release Checkpoint

## Release identity

This document describes the Director-accepted ViewWright `0.1.0` repository release checkpoint: the accepted M0–M39 system. It is a project release checkpoint, not a claim that packages have been published to crates.io.

## What this release represents

ViewWright authors normative interface intent in declarative TOML, resolves it into a typed semantic blueprint, and projects that intent through layout planning, ASCII, concept specifications, visual audit, and the current egui backend. Fixtures support representative states in an isolated preview. Semantic identity is carried into egui's AccessKit output.

ViewWright remains the authority for what an interface should be. ViewWitness remains the authority for descriptive runtime observations of what is. Their models are not merged. M33 provides typed normative expectations; M35 compares exact shared evidence; M38 proves the full chain against real AccessKit-enabled ViewWright renderer output converted directly into a ViewWitness Witness. The accepted M38 cases—Project Browser, M31 overlay pressure, and M32 overflow pressure—each validate and compare with zero mismatches and zero evidence gaps.

The current renderer backend is egui. M38 is an in-process test proof, not a live observer/server, continuous verification service, or public runtime API. Comparison is exact, not fuzzy.

## Intentional deferrals

- Authored responsive layout remains the unpromoted roadmap in [Issue #33](https://github.com/sguzman/viewwright/issues/33); no breakpoints, variants, or resize rules are included.
- Live ViewWitness observer/server orchestration, network capture, and external-process integration.
- Public runtime verification APIs, preview verification controls, recurring checks, and CI gates.
- Fuzzy/tolerant comparison, screenshot/paint/raster comparison, and backend-independent element geometry.
- Fixture-aware expectation semantics, general application state/data binding, and additional GUI backends.

This checkpoint establishes no crates.io publication commitment, no MSRV promise, and no broader production-stable API compatibility guarantee beyond the project's existing declarations and accepted behavior.

## Release finalization

Director acceptance of M39 is complete. Release finalization should create and push an annotated `v0.1.0` tag at this release-finalization commit. This checkpoint does not create a GitHub Release or publish to crates.io.
